# Retiring the C++/Qt application: what the Rust application still has to cover

Decision (Daniel, 2026-11-18): Vortia keeps only the Rust version. The C++/Qt
application (`src/`, the macOS SwiftUI edition under `platforms/apple`, and
`vortia-engine`) is removed **in stages, when the Rust application covers what it
does**, not before: today the published installers, the release workflow and the
download on the website are all the C++ application, and removing it first would
leave Vortia with nothing to download. Nothing is deleted until the last row of
the table below is done.

This file is the list. A row is "done" when the Rust application does the same
thing with a test or a recorded result, not when a screen exists.

## What the Rust application has today

The engine (`vortia-solvers`: laplacian, scalar transport, `icoFoam`, `simpleFoam`
laminar, k-ε and k-ω SST, `rhoSimpleFoam`, the compressible nozzle solver, natural
convection), mesh import (Gmsh, Fluent `.msh`, CGNS) and `blockMesh`, `checkMesh`,
post-processing (probes, lines, patch and volume statistics, wall quantities,
streamlines, slices, CSV and VTK export), and an egui application in the Nodalia
engineering window: open a case, run it, watch residuals, edit conditions,
numerics and schemes, look at the mesh and fields.

## What only the C++/Qt application has

Checked against the source headers in `src/` and a search of `rust/` (no sketch,
STL, updater, issue-report or translation code exists there).

## Progress

- **R1, done on 2026-11-18** (all but one clause): Home "New" and `vortia new` make a 2D channel
  (`simpleFoam`) or a planar or axisymmetric nozzle (`rhoSimpleFoam`, k-ω SST) with the case,
  its block mesh and its fields written by Rust (`rust/vortia-cases`). The three meshes have the
  same cells, points and faces, and "Mesh OK", as OpenFOAM v1912's `blockMesh` and `checkMesh`
  on the same `blockMeshDict` (a test that runs when OpenFOAM is installed). Not done:
  `examples/nozzle-practice-2026` is a nozzle that discharges into an open atmosphere region,
  which the new nozzle cases do not have; making that case from the app belongs with R4 (physics
  setup), where the boundaries are chosen. The planar nozzle is the whole slot, not the Qt
  application's half section: the compressible solver has no symmetry condition for T, k and
  omega yet (an engine task for R4).
- **R5, started on 2026-11-18:** the mass balance (`Case::mass_balance` and
  `mass_balance_history` in `rust/vortia-post`, `vortia balance`, a card in the Run tab) reads
  the written `phi`, as the Qt `nozzleMassBalance` does. The residual plot of the Run tab
  (initial residuals by field from the solver log, logarithmic) is done. Pause and resume of a run
  (a ribbon button, the File and Case menus and the command search; `vortia_solvers::cancel::with_control`)
  hold the engine at the start of its next step and a stop still ends a paused run. The residual card warns while a run goes wrong (a residual
  that is not a number, or that is back at 1 or above after falling by three decades or more).
- **R6, on 2026-11-18:** the section analysis (`Case::section` in `rust/vortia-post`, `vortia
  section`, a card in the Results tab) integrates the stored fields over a plane cut through the
  cells and the report is written as sealed JSON (a SHA-256 of its canonical payload, in the
  `vortia_post::seal` envelope), CSV or HTML in `postProcessing/section/<time>/`. Forces and
  moments on walls (`vortia_post::forces`, `vortia forces`, a Forces card in the Results tab) give
  pressure and viscous parts and the coefficients against a reference density, speed, area and
  length; a kinematic case reports force per unit density, and a gas without a reference density
  is refused. `vortia compare NUMBER BASELINE REPORT...` compares two sealed reports and refuses those whose
  definitions differ. Still to do for R6: the comparison in the app (it is CLI-only for now).

- **R8, on 2026-11-18:** the app speaks English or Spanish (`rust/vortia-app/src/i18n.rs`: the
  system language by default, a selector in Preferences, English as the key and anything the
  table lacks left in English). The problem report (`vortia-app/src/report.rs`: a GitHub
  new-issue draft with the version, the system and the solver, never a path) and STL import
  (`vortia_mesh::stl`, shown on Home with its size, area, volume and open edges) are done. Still
  to do for R8: Fluent `.cas.h5`/`.dat.h5` viewing and the updater (which waits for the Rust
  releases).

- **R7, started on 2026-11-18:** `vortia_post::gci` (the three-mesh index, checked against
  `benchmarks/common/gci.py`) and `rust/vortia-cli/tests/verification.rs`, which runs a Poiseuille
  channel from `vortia-cases` through the engine in the normal `cargo test`: profile within 3 %
  of the peak and, with three meshes, observed order 1.96 and the extrapolated mid-plane speed
  within 0.01 % of the exact one; and the lid-driven cavity (a new case type, `vortia new cavity`,
  its mesh identical to OpenFOAM's) against both Ghia centre-line tables at Re = 100 within 0.9 %
  of the lid speed. Still to do for R7: the nozzle against OpenFOAM, and a three-mesh index for the cavity, all in `cargo test`.
  Blasius is done (a new `vortia new plate` case, with a slip wall ahead of the plate, which
  needed `slip`/`symmetry` for vectors in the incompressible engine): mean and local friction
  coefficient within 1.5 % and the profile within 0.65 % of the stream speed, and OpenFOAM's
  `simpleFoam` on the same case agrees on the wall stress to 0.1 %. The turbulent plate is a test now too
  (`vortia new plate-turbulent`, k-ω SST with wall functions, C_D within the 15 % band fixed
  beforehand: −10.2 %, as OpenFOAM's).

- **R4, started on 2026-11-18:** Setup has Fluid, Turbulence and Viscosity views that edit
  `constant/thermophysicalProperties`, `turbulenceProperties` and `transportProperties` in place,
  beside the boundary conditions, run settings, numerics and schemes that were already there.
  The turbulence model, simulation type and energy variable are pick-lists of what the engine
  has. The boundary type of each patch the mesh does not decide is a pick-list too (fixedValue,
  noSlip, zeroGradient, and slip and symmetry for `icoFoam` and `simpleFoam`; fixedValue,
  zeroGradient and fixedGradient for scalars): choosing one writes the patch block again with the
  entries the new type needs, such as `value` or `gradient`. Still to do for R4: a symmetry
  condition in the compressible engine and a jet-into-atmosphere nozzle case.

## Order

R1, then R4 and R5 (a case can be made and run entirely in the Rust app), then
R6 and R7 (what it shows can be trusted), R2 and R3 (new geometry), R8, R9, and
R10 and R11 last. R9 can move earlier if a Rust-only release is wanted sooner.

## Packaging (R9)

Started on 2026-11-18: `rust/packaging/linux/package.sh` builds the Rust app and the `vortia`
tool into a tarball and an AppImage (no OpenFOAM inside), and `.github/workflows/rust-packages.yml`
runs it on Ubuntu 22.04 for changes under `rust/packaging/`, keeping the files as workflow
artifacts. Nothing is attached to a release yet: the release flow keeps shipping the C++
application, reading its version from `CMakeLists.txt`, until the cutover. The macOS DMG
(`rust/packaging/macos/package.sh`, built by the same workflow on `macos-15`) puts `Vortia.app`
(the app and the `vortia` tool, signed ad hoc, not notarized) in the installer window of the
existing app. It could only be written, not run, on the Linux machine that made it, so the
workflow is its first test. Still to do: the release workflow reading `rust/Cargo.toml`, the website, and
the in-app updater (`nodalia-update`), which stays off until the Rust app has releases of its own,
or it would offer the C++ installers over the Rust app.

## The mesher (R3)

Decided on 2026-11-18, from Daniel's all-Rust rule: Vortia gets its own 2D mesher in Rust
(structured and unstructured, enough for nozzles and channels). The Qt application's Gmsh is
GPL and not Rust, so it is not used or bundled unless Daniel says otherwise.

Progress: the `vortia-sketch` crate holds the dimensioned sketch (points, lines, arcs,
constraints), its solver, the templates (duct, nozzle, rounded nozzle) and a versioned file
format. A sketched wall becomes a structured block mesh through `Nozzle::from_sketch`, and the
CLI reaches it with `vortia sketch template|info` and `vortia new sketch`. Home's "New > From
sketch" in the app starts from a template, edits its dimensions (an edit that cannot be solved is
refused and the sketch stays as it was), draws the wall and keeps `sketch.vortia-sketch` in the
case. Still to do: drawing new lines and arcs and dragging points on the canvas, snapping, adding
dimensions, opening a saved sketch, and a general mesher for shapes that are not a profile of revolution or extrusion.

## What this changes in the public text

Until R11, the README, the website and the releases keep describing what the
published installers are. They are not edited to say the C++ application is gone.
